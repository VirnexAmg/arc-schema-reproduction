# Working notes

## Grounded objects
- Main playfield is a 5-pixel lattice maze: color 3 is traversable corridor; color 4 is wall/exterior.
- Movable 5x5 token has color 12 in its top two rows and color 9 in its bottom three.
- Rows 61-62 are a 42-step attempt strip.
- The branch cell at x=19,y=30 contains a reusable embedded 0/1 glyph hidden by the token while occupied.
- The framed color-5/9 pattern near x=32..40,y=8..16 is a target/display terminal.
- Lower HUD rows 55-60 encode a 3x3 binary register.

## Established mechanisms
- ACTION1=up, ACTION2=down, ACTION3=left, ACTION4=right.
- Legal actions shift the token by one 5-pixel cell; walls block.
- Vacating the marker restores its glyph; entries can transform the HUD.
- Full checked timeline backtests exactly.
- At terminal x=34,y=15, ACTION1 is an inert submission attempt when the register is wrong; ACTION3 is a consuming wall collision.
- Meter exhaustion causes the following action to reset token, meter, HUD to 111/100/101, and status lamps.

## Latest experiment
- After reset HUD 111/100/101, leaving and re-entering the marker from the left changed it to 111/001/101 again.
- This rules out a monotonic hidden schedule continuing across meter exhaustion and supports a resettable cycle/state machine.
- Token is currently on marker x=19,y=30 with HUD 111/001/101.

## Competing hypotheses
- H1: Marker transformation depends only on current HUD plus a resettable internal phase; another left entry continues the previously observed sequence.
- H2: Transformation depends on entry direction. Entering from below may apply a distinct operation useful for moving the middle-row bit toward target column 2.
- H3: Transformation depends on attempt-strip phase as well as HUD, though the exact repeat after exhaustion shows that exhaustion resets the relevant phase.
- Literal target equality 111/010/101 remains the strongest submission hypothesis.

## Ruled out
- Meter exhaustion preserves neither assembled HUD nor phase.
- Up at terminal does not submit an incorrect HUD.
- Transform-on-every-entry is false because one earlier entry was inert.
- The 101/001/111 state is not a permanent fixed point.
- The post-reset next entry does not continue to an unseen later hidden phase; it repeats initial -> 111/001/101.

## Needs testing
- From the current marker cell, ACTION2 exits downward to x=19,y=35 and ACTION1 re-enters from below. Compare its result with another entry from the left to test direction dependence.
- If direction changes the operation, search alternate approaches for target 111/010/101.
- Derive marker operation from its embedded glyph/status lamps rather than hard-coded attempt thresholds.

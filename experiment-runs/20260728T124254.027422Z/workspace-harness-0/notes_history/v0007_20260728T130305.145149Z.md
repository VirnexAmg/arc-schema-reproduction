# Working notes

## Objects
- A movable 5x5 token has a 2x5 color-12 cap and 3x5 color-9 body.
- Color 3 and room-floor color 5 are traversable; color 4 is wall.
- A 0/1 glyph is a traversable control and may be hidden under the token.
- The upper patterned chamber is a target/goal area, but its partial 12/9 rendering can resemble the token.
- The lower-left 9/5 motif is a status display.
- The two-row color-11 strip is a movement budget; spent cells become color 3.

## Established mechanisms
- ACTION1=up, ACTION2=down, ACTION3=left from direct transitions; ACTION4 is inferred right.
- Successful token motion is in 5-pixel increments.
- Crossing/leaving the control changes the lower status motif and restores its hidden glyph.

## Current mismatch / falsified hypotheses
- Full replay still mismatches at the seventh checked transition, ACTION2, by exactly one budget column; geometry otherwise agrees.
- Component-aware token grounding was tested. Requiring two complete token silhouettes immediately broke the first transition, proving that the level normally has only one complete movable 12/9 silhouette; the upper target is not a second complete token.
- Restoring single-component grounding returns the original meter-only mismatch. Thus mistaken selection between two complete tokens is ruled out as the cause.
- Simple claims that all downward actions spend, or that all downward actions are free, are inadequate: source state/context controls the meter effect, and the current code's blanket downward-free rule still does not explain replay behavior.

## Competing hypotheses
- H1: ACTION2 from a special upper-target state is a free no-op, while ordinary downward corridor movement spends.
- H2: control/status state grants exactly one refunded return action, after which downward moves spend normally.
- H3: budget updates are delayed or coupled to attempted rather than displayed token motion.

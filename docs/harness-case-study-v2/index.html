01 / 先把题意对齐

同一条通关路径，两种完全不同的解释

画面行为相似，不等于内部机制相同。真正要裁决的是：模型有没有把视觉符号的因果关系说出来并写进模拟器。

已知正确机制

十字是一条“旋转”指令

↻ =

图形对齐后，再走到对应位置，环境才会把 levels_completed 从 0 改成 1。

本局写下的解释

十字被当成“可捡的 0/1 图标”

“The small 0/1 glyph is a collectible… changes the matching inventory glyph below the maze.”
  1. 移动：ACTION 1–4 被建模成 5×5 玩家上下左右走格。
  2. 拾取：走到十字所在格，被解释为捡起钥匙 / collectible。
  3. 出口：再走进上方 framed symbol / chamber。
  4. 记忆：最终用 (34, 15) + ACTION1 硬编码升关。

差距不在“有没有走到” 而在“为什么要先走十字，再去目标”

真实答案是旋转与图形匹配；模型答案是捡钥匙与进房间。

04 / 背景，不是主结论

Harness 有用，但这次有用在“可执行迭代”

它迫使模型把猜测变成代码，再用历史转移校验，因而能比只看一次画面更快形成可行动策略。可惜，回测只保证“复现已见行为”，不保证“解释了真实机制”。
